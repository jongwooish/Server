## 1. AD インストールの準備

Active Directory を提供するサーバーを**ドメインコントローラー（DC）** と呼びます。サーバーを DC にするには、準備しておくことがあります。

- **以前の方法（2012 より前）**: `DCPROMO` コマンドを使っていました。
- **現在の方法（2012 以降）**: サーバーマネージャー（Server Manager）のリモート管理機能が強化されてインストール方法が変わり、サーバーマネージャーで **DC への昇格**を行います。

### DC インストールの必須条件

- **固定 IP の使用**: DC は必ず**固定 IP（Static IP）** を使います。
- **DNS 設定**: AD をインストールするサーバーは、優先 DNS に**自分自身の IP アドレス**（`127.0.0.1` または自分の IP）を設定します。
  - 現在は AD のインストール時に、サーバーが自動で優先 DNS を自分自身に変更してくれます。（以前はそうではなく、問題が多かったそうです。）
- **コンピューター名の設定**: サーバー名をあらかじめ決めておきます。（例: `DC01`、`DC02`）

## 2. ドメインコントローラーのインストール手順

役割を追加してから DC に**昇格（Promotion）** する、2 つの段階で進めます。

1. **役割と機能の追加**: サーバーマネージャーのダッシュボードで**役割と機能の追加**をクリックします。
2. **サービスの選択**: **Active Directory ドメインサービス**にチェックを入れます。AD の管理に必要な管理ツールも一緒にインストールされます。
3. **基本モジュールのインストール**: インストールを押すと、AD の基本モジュールと管理ツールがインストールされます。
4. **DC への昇格**: インストールが終わるとサーバーマネージャーに**このサーバーをドメインコントローラーに昇格する**リンクが表示され、クリックするとウィザードが始まります。
5. **機能レベルの選択**: 特に理由がなければ、**最も高いバージョン**を選ぶのがよいです。
6. **GC/DNS の確認**: 最初の DC ではグローバルカタログと DNS サーバーが必須なので、自動で選択されます。
7. **DSRM パスワード**: DC に問題が起きたときに使う**ディレクトリサービス復元モード**のパスワードを設定します。
8. **再起動**: パスを確認してインストールを押します。インストールが終わるとサーバーは自動で再起動します。

### 昇格のオプション

| オプション | 選ぶとき |
| --- | --- |
| 新しいフォレストを追加する | ドメインを**初めて**作るとき |
| 既存のドメインに DC を追加する | すでに DC があり、バックアップや負荷分散のために DC を**もう 1 台**追加するとき |

> **NetBIOS 名**: ドメイン名が `korea.com` なら NetBIOS 名は `KOREA` になります。NetBIOS 名は**最大 15 文字**までです。

## 3. DNS と AD の関係（SRV レコード）

AD は **DNS なしには存在できません。** AD はすべてのコンピューターの情報を DNS を通じて探します。

### DNS とは？

- コンピューター名を IP アドレスに変換する役割です。
- **FQDN**（Fully Qualified Domain Name）: ホスト名（例: `www`）とドメイン名（例: `koala.com`）を合わせた完全な名前（`www.koala.com`）です。

### SRV レコードとは？

- **SRV（Service）レコード**は、名前の先頭に `_`（アンダースコア）が付いたレコードです。（例: `_ldap._tcp.dc._msdcs.korea.com`）
- GC を探すには **3268 番**ポート、Kerberos 認証には **88 番**ポートを使う、といった情報が SRV レコードに入っています。
- DC が複数あれば SRV レコードも複数登録され、DC を探すときに**ラウンドロビン**方式で負荷が分散されます。
- AD をインストールすると、DC の SRV レコードが**自動で登録**されます。

## 4. クライアントのドメイン参加

### 参加前に必須: DNS 設定

- クライアントは DNS 設定に **DC の IP アドレス**を指定しないと、DC を見つけられません。
- DNS が DC を指していないと、**ドメイン参加（AD join）はできません。**

### 参加方法（GUI）

| 方法 | 内容 |
| --- | --- |
| 簡単な変更 | システムのプロパティでドメイン名だけを入力して参加します。ドメインアカウントにローカル権限を与えるには、コンピューターの管理でグループに直接追加する必要があります。 |
| ネットワーク ID | システムのプロパティの**ネットワーク ID** ウィザードを使います。ドメイン参加と同時に、ユーザーアカウントにクライアント PC の**ローカル管理者権限**まで一度に与えられます。 |

### クライアントが DC を探す順序

クライアントがログオンやドメイン参加のために DC を探すときは、**必ず DNS** を使います。

![How a client finds a DC](../images/ad-dc-locator.svg)

1. **DNS に問い合わせ**: クライアントが自分の DNS サーバーにドメインの **SRV レコード**を問い合わせます。
2. **DC の一覧を取得**: DNS が SRV レコード（DC のアドレス）の一覧を返します。
3. **ping で確認**: 受け取った DC の一覧に ping を送り、生きている DC を確認します。
4. **最適な DC を選択**: 応答がいちばん速い DC を選んで認証を試みます。

## 5. DNS の発展的な概念

![Name resolution order and query types](../images/ad-name-resolution.svg)

### 名前解決の順序

コンピューターは名前を探すとき、いきなり DNS サーバーに問い合わせるのではなく、次の順で確認します。

1. **ローカルのホスト名**（自分自身）
2. **hosts ファイル**（`C:\Windows\System32\drivers\etc\hosts`）
3. **ローカルの DNS キャッシュ**: 以前 DNS から受け取った IP 情報
4. **DNS サーバーに問い合わせ**

### DNS クエリの種類

| 種類 | 説明 | 方向 |
| --- | --- | --- |
| 再帰クエリ（Recursive） | クライアントが DNS サーバーに**最終的な答え**を要求します。 | クライアント ⇄ サーバー |
| 反復クエリ（Iterative） | DNS サーバーが正確な答えを得るために、ルート、TLD、権威サーバーなど**ほかのサーバーに繰り返し**問い合わせます。 | サーバー ⇄ サーバー |

## まとめ

- DC には**固定 IP**、**自分自身を指す DNS**、**あらかじめ決めたコンピューター名**が必要です。2012 からは `DCPROMO` の代わりに**サーバーマネージャー**で昇格します。
- インストールは **AD DS 役割の追加 → DC への昇格**（新しいフォレスト / 既存ドメインに追加）→ 機能レベル → GC/DNS → **DSRM パスワード** → 再起動の順です。NetBIOS 名は最大 **15 文字**です。
- AD は **DNS なしでは動きません。** `_` で始まる **SRV レコード**が自動登録され、DC・GC（3268）・Kerberos（88）を見つけられるようにします。
- クライアントは **DNS を DC に向けないと**ドメインに参加できません。**ネットワーク ID** ウィザードはローカル管理者権限も一緒に与えます。
- DC の探し方: **SRV の問い合わせ → DC 一覧 → ping → 最速の DC** です。
- 名前解決の順序は **ローカルのホスト名 → hosts ファイル → キャッシュ → DNS サーバー**で、クエリは**再帰**（クライアント↔サーバー）と**反復**（サーバー↔サーバー）に分かれます。
