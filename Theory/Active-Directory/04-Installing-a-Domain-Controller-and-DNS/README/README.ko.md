## 1. AD 설치 준비

Active Directory를 서비스하는 서버를 **도메인 컨트롤러(DC)** 라고 부릅니다. 서버를 DC로 만들려면 준비할 것이 있습니다.

- **예전 방식 (2012 이전)**: `DCPROMO` 명령어를 사용했습니다.
- **지금 방식 (2012 이후)**: 서버 관리자(Server Manager)의 원격 관리 기능이 강화되면서 설치 방법이 바뀌었고, 서버 관리자에서 **DC 승격** 작업을 합니다.

### DC 설치 필수 조건

- **고정 IP 사용**: DC는 반드시 **Static IP**를 써야 합니다.
- **DNS 설정**: AD를 설치하는 서버는 기본 DNS에 **자기 자신의 IP 주소**(`127.0.0.1` 또는 자기 IP)를 넣어야 합니다.
  - 요즘은 AD를 설치할 때 서버가 알아서 기본 DNS를 자기 자신으로 바꿔 줍니다. (예전에는 그렇지 않아 문제가 많았습니다.)
- **컴퓨터 이름 설정**: 서버 이름을 미리 정해 둡니다. (예: `DC01`, `DC02`)

## 2. 도메인 컨트롤러 설치 과정

역할을 추가한 다음 DC로 **승격(Promotion)** 하는 두 단계로 진행합니다.

1. **역할 및 기능 추가**: 서버 관리자 대시보드에서 **역할 및 기능 추가**를 클릭합니다.
2. **서비스 선택**: **Active Directory 도메인 서비스**를 체크합니다. AD 관리에 필요한 관리 도구도 함께 설치됩니다.
3. **기본 모듈 설치**: 설치를 누르면 AD의 기본 모듈과 관리 도구가 설치됩니다.
4. **DC로 승격**: 설치가 끝나면 서버 관리자에 **이 서버를 도메인 컨트롤러로 승격** 링크가 나타나고, 클릭하면 마법사가 시작됩니다.
5. **기능 수준 선택**: 특별한 이유가 없다면 **가장 높은 버전**을 선택하는 것이 좋습니다.
6. **GC/DNS 확인**: 첫 DC에서는 글로벌 카탈로그와 DNS 서버가 필수라서 자동으로 선택됩니다.
7. **DSRM 암호**: DC에 문제가 생겼을 때 사용하는 **디렉터리 서비스 복원 모드**의 암호를 설정합니다.
8. **재부팅**: 경로를 확인하고 설치를 누릅니다. 설치가 끝나면 서버가 자동으로 재부팅됩니다.

### 승격 옵션

| 옵션 | 언제 선택하나 |
| --- | --- |
| 새 포리스트 추가 | 도메인을 **처음** 만들 때 |
| 기존 도메인에 DC 추가 | 이미 DC가 있고, 백업이나 부하 분산을 위해 DC를 **한 대 더** 추가할 때 |

> **NetBIOS 이름**: 도메인 이름이 `korea.com`이면 NetBIOS 이름은 `KOREA`가 됩니다. NetBIOS 이름은 **최대 15자**까지 가능합니다.

## 3. DNS와 AD의 관계 (SRV 레코드)

AD는 **DNS 없이는 존재할 수 없습니다.** AD는 모든 컴퓨터 정보를 DNS를 통해 찾습니다.

### DNS란?

- 컴퓨터 이름을 IP 주소로 바꿔 주는 역할을 합니다.
- **FQDN** (Fully Qualified Domain Name): 호스트 이름(예: `www`)과 도메인 이름(예: `koala.com`)을 합친 전체 이름(`www.koala.com`)입니다.

### SRV 레코드란?

- **SRV(Service) 레코드**는 이름 앞에 `_`(언더바)가 붙은 레코드입니다. (예: `_ldap._tcp.dc._msdcs.korea.com`)
- GC를 찾으려면 **3268번** 포트, Kerberos 인증에는 **88번** 포트를 쓴다는 정보가 SRV 레코드에 들어 있습니다.
- DC가 여러 대면 SRV 레코드도 여러 개 등록되고, DC를 찾을 때 **라운드 로빈** 방식으로 부하가 분산됩니다.
- AD를 설치하면 DC의 SRV 레코드가 **자동으로 등록**됩니다.

## 4. 클라이언트의 도메인 가입

### 가입 전 필수: DNS 설정

- 클라이언트는 DNS 설정에 **DC의 IP 주소**를 지정해야 DC를 찾을 수 있습니다.
- DNS가 DC를 가리키지 않으면 **도메인 가입(AD join)이 되지 않습니다.**

### 가입 방법 (GUI)

| 방법 | 내용 |
| --- | --- |
| 간단한 변경 | 시스템 속성에서 도메인 이름만 입력하고 가입합니다. 도메인 계정에 로컬 권한을 주려면 컴퓨터 관리에서 그룹에 직접 추가해야 합니다. |
| 네트워크 ID | 시스템 속성의 **네트워크 ID** 마법사를 사용합니다. 도메인 가입과 동시에 사용자 계정에 클라이언트 PC의 **로컬 관리자 권한**까지 한 번에 줄 수 있습니다. |

### 클라이언트가 DC를 찾는 순서

클라이언트가 로그온하거나 도메인에 가입하려고 DC를 찾을 때는 **반드시 DNS**를 이용합니다.

![How a client finds a DC](../images/ad-dc-locator.svg)

1. **DNS에 질의**: 클라이언트가 자기 DNS 서버에 도메인의 **SRV 레코드**를 물어봅니다.
2. **DC 목록 획득**: DNS가 SRV 레코드(DC들의 주소) 목록을 보내 줍니다.
3. **핑 확인**: 받은 DC 목록에 핑을 보내 살아 있는 DC를 확인합니다.
4. **최적 DC 선택**: 응답이 가장 빠른 DC를 골라 인증을 시도합니다.

## 5. DNS 심화 개념

![Name resolution order and query types](../images/ad-name-resolution.svg)

### 이름 확인 순서

컴퓨터가 이름을 찾을 때 DNS 서버에 바로 묻지 않고, 다음 순서대로 확인합니다.

1. **로컬 호스트 이름** (자기 자신)
2. **hosts 파일** (`C:\Windows\System32\drivers\etc\hosts`)
3. **로컬 DNS 캐시**: 이전에 DNS에서 받아 온 IP 정보
4. **DNS 서버에 질의**

### DNS 질의 종류

| 종류 | 설명 | 방향 |
| --- | --- | --- |
| 재귀 쿼리 (Recursive) | 클라이언트가 DNS 서버에게 **최종 답**을 요청합니다. | 클라이언트 ⇄ 서버 |
| 반복 쿼리 (Iterative) | DNS 서버가 정확한 답을 얻으려고 루트, TLD, 권한 있는 서버 등 **다른 서버와 반복해서** 묻습니다. | 서버 ⇄ 서버 |

## 정리

- DC는 **고정 IP**, **자기 자신을 가리키는 DNS**, **미리 정한 컴퓨터 이름**이 필요합니다. 2012부터는 `DCPROMO` 대신 **서버 관리자**에서 승격합니다.
- 설치는 **AD DS 역할 추가 → DC 승격**(새 포리스트 / 기존 도메인에 추가) → 기능 수준 → GC/DNS → **DSRM 암호** → 재부팅 순서입니다. NetBIOS 이름은 최대 **15자**입니다.
- AD는 **DNS 없이는 동작하지 않습니다.** `_`로 시작하는 **SRV 레코드**가 자동 등록되어 DC·GC(3268)·Kerberos(88)를 찾게 해 줍니다.
- 클라이언트는 **DNS를 DC로 지정**해야 도메인에 가입할 수 있습니다. **네트워크 ID** 마법사는 로컬 관리자 권한까지 함께 줍니다.
- DC 찾기: **SRV 질의 → DC 목록 → 핑 → 가장 빠른 DC**입니다.
- 이름 확인 순서는 **로컬 호스트 이름 → hosts 파일 → 캐시 → DNS 서버**이고, 질의는 **재귀**(클라이언트↔서버)와 **반복**(서버↔서버)으로 나뉩니다.
