## 1. AD를 사용하는 핵심 목표

### 싱글 사인온 (SSO)

**AD를 사용하는 가장 큰 이유**는 **SSO(Single Sign-On)** 환경을 만드는 것입니다.

- **AD가 없을 때 (작업 그룹)**: 컴퓨터가 10대라면 계정을 10대에 **각각** 만들어야 하고, 암호를 바꿀 때도 10번 작업해야 합니다.
- **AD가 있을 때 (도메인)**: 중앙 서버인 **도메인 컨트롤러(DC)** 가 인증을 처리합니다. 계정 하나로 **회사 안의 모든 인프라를 이용하도록 설계**할 수 있습니다.
- **AD의 목적**: **계정 관리**, **인증 처리**(누구인지 증명), **인가 처리**(무엇을 할 수 있는지)를 한 곳에서 **중앙 집중적으로** 수행합니다.

![Workgroup vs Domain](../images/ad-workgroup-vs-domain.svg)

### 왜 '디렉터리'일까?

- **디렉터리**: 파일 시스템의 '폴더'가 아니라 **전화번호부**에 가까운 의미입니다. 사내 인프라에서 쓰는 계정, 그룹 등 **여러 정보를 담아 두는 저장소**입니다.
- **Active의 의미**: 종이 전화번호부처럼 고치기 어려운 것이 아니라, **원할 때 정보를 손쉽게 생성·수정·변경·삭제**할 수 있다는 뜻에서 **"살아 있는 전화번호부"** 라고 부릅니다.
- **AD 등장 이전**: Windows NT 4.0까지는 계정 정보를 **SAM**(Security Account Manager) 데이터베이스에 저장했습니다.

## 2. 보안 아키텍처의 기본: 인증과 인가

AD 구조에서 신원 확인과 접근 제어를 이해하려면 꼭 알아야 하는 두 개념입니다.

### 인증 (Authentication)

- **정의**: "내가 누구인지 증명하는 작업"입니다.
- **작동 방식**: 사용자가 계정과 암호를 입력하면 인증 요청이 **도메인 컨트롤러(DC)** 로 전송되고, DC에 저장된 정보와 일치하면 그 사용자가 맞다고 **확인**해 줍니다.

### 인가 (Authorization)

- **정의**: **누가 무엇을 할 수 있는지 없는지**를 판단하는 것입니다.
- 인가에는 **권한(Right)** 과 **사용 권한(Permission)** 두 종류가 있습니다.

| 구분 | 권한 (Right) | 사용 권한 (Permission) |
| --- | --- | --- |
| 정의 | 무언가를 **할 수 있는** 허가 | 무언가를 **쓸 수 있는** 허가 |
| 예시 | 컴퓨터 종료, 네트워크에서 컴퓨터 접근, 원격 데스크톱 접속 | 폴더 읽기, 파일 쓰기 |
| 중요 특징 | Administrator는 모든 권한을 가지고 있어 슈퍼 계정이라고 부릅니다. | 해당 개체의 **소유자만** 부여할 수 있습니다. |
| 소유권 | 남의 개체의 사용 권한을 바꾸려면 **소유권 가져오기** 권한이 따로 있어야 합니다. | — |

## 3. 데이터 보안 방식: 암호화

네트워크 통신에서 데이터를 보호하는 방식입니다.

![Symmetric, asymmetric and hybrid encryption](../images/ad-encryption.svg)

### 대칭키 암호화

- **특징**: **암호화하는 키와 복호화하는 키가 같은** 구조입니다.
- **장점**: 처리가 쉽고 속도가 빠릅니다.
- **단점**: 암호화된 데이터를 받는 사람에게 **키를 안전하게 전달**해야 하는 문제가 있습니다.

### 비대칭키 암호화

- **특징**: **키가 두 개**(비대칭)입니다.
  - **공개 키 (Public Key)**: 암호화할 때 쓰고, 다른 사람과 공유합니다.
  - **개인 키 (Private Key)**: 복호화할 때 쓰고, **절대 공유하지 않습니다**.
- **작동 방식**: 데이터를 상대방의 **공개 키**로 암호화하면, 그 상대방의 **개인 키**로만 복호화할 수 있습니다.
- **기반 기술**: 인증서·인증 기관 기술, 즉 **PKI**(Public Key Infrastructure)의 기반입니다.
- **장점**: 보안성이 훨씬 뛰어납니다.

### 전자 서명 (Digital Signature)

- **목적**: 이 데이터를 **보낸 사람이 정말 그 사람인지**(신원)를 증명합니다.
- **작동 방식**: 발신자가 자신의 **개인 키**로 서명하면, 수신자는 발신자의 **공개 키**로 확인합니다.

### 하이브리드 암호화 (혼합 방식, HTTPS)

- 대부분의 암호화 솔루션은 비대칭키의 **보안성**과 대칭키의 **속도**를 결합한 하이브리드 방식을 사용합니다.
- **원리**: 가장 중요한 **대칭 키** 자체는 안전한 **비대칭 키** 방식으로 암호화해 전달하고, 그 **이후의 대용량 데이터 통신**은 빠르고 효율적인 **대칭 키** 방식으로 진행합니다.

## 4. 도메인 vs 작업 그룹

Windows 환경에서 **인증을 누가 관리하느냐**에 따른 구분입니다.

| 구분 | 작업 그룹 (Workgroup) | 도메인 (Domain) |
| --- | --- | --- |
| 기본 설정 | Windows 설치 시 기본값입니다. | Active Directory를 구성해서 설정합니다. |
| 인증 주체 | 각 컴퓨터가 로컬에서 계정과 암호를 관리합니다. (로컬 인증) | 중앙 시스템인 도메인 컨트롤러(DC)가 인증을 처리합니다. |
| AD 연결 | AD에 연결되어 있지 않습니다. | 도메인에 연결하는 것을 "도메인에 가입한다"고 표현합니다. |
| 장점 | 단순하고 개별 관리가 가능해 소규모 환경에 적절합니다. | SSO가 가능하고, 한 곳에서 보안과 인증·인가를 모두 관리합니다. |
| 단점 | 컴퓨터마다 계정과 암호를 따로 입력해야 합니다. | 중앙 시스템(DC)이 망가지면 인증 체계 전체가 동작하지 않습니다. |

> 두 방식을 가르는 핵심은 **ID에 대한 인증(Authentication)을 누가 하느냐**입니다.

## 5. 한눈에 보는 비유

AD 환경은 **중앙 도서관 시스템**과 같다고 생각하면 됩니다.

- 중앙 도서관(**DC**)에 신분을 등록(**계정 생성**)하면, 발급받은 회원증 하나(**SSO**)로 회사 안의 모든 자료실(**컴퓨터, 서버**)을 이용할 수 있습니다.
- 각 자료실은 이 회원증이 유효한지 **중앙 도서관에 물어보고** 문을 열어 줍니다.
- 도서관이 문을 닫거나(**DC 장애**) 회원증이 취소되면(**계정 삭제**), 그 사람은 더 이상 어떤 자료실에도 들어갈 수 없습니다.

## 정리

- AD의 가장 큰 목적은 **SSO**입니다. 계정 관리·인증·인가를 **DC 한 곳에서 중앙 집중적으로** 처리합니다.
- **디렉터리**는 계정과 그룹 정보를 담은 '전화번호부'이고, **Active**는 언제든 고칠 수 있는 '살아 있는' 전화번호부라는 뜻입니다. AD 이전(NT 4.0)에는 **SAM**을 썼습니다.
- **인증**은 "누구인가", **인가**는 "무엇을 할 수 있는가"입니다. 인가는 **권한(Right)** 과 **사용 권한(Permission)** 으로 나뉩니다.
- **대칭키**는 빠르지만 키 전달이 문제이고, **비대칭키**는 안전하며 **PKI**와 **전자 서명**의 기반입니다. 실제로는 둘을 섞은 **하이브리드 방식**(HTTPS)을 씁니다.
- **작업 그룹**은 로컬 인증, **도메인**은 DC가 인증합니다. 도메인은 편리하지만 DC가 멈추면 인증도 멈추므로 DC를 이중화합니다.
