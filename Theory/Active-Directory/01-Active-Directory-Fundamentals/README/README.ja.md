## 1. AD を使う主な目的

### シングルサインオン（SSO）

**AD を使う最大の理由**は、**SSO（Single Sign-On）** 環境をつくることです。

- **AD がない場合（ワークグループ）**: コンピューターが 10 台あれば、アカウントを 10 台それぞれに**個別に**作り、パスワード変更も 10 回行う必要があります。
- **AD がある場合（ドメイン）**: 中央のサーバーである**ドメインコントローラー（DC）** が認証を処理します。1 つのアカウントで**社内のすべてのインフラを使えるよう設計**できます。
- **AD の目的**: **アカウント管理**、**認証**（誰であるかの証明）、**認可**（何ができるか）を 1 か所で**集中的に**行います。

![Workgroup vs Domain](../images/ad-workgroup-vs-domain.svg)

### なぜ「ディレクトリ」なのか？

- **ディレクトリ**: ファイルシステムの「フォルダー」ではなく、**電話帳**に近い意味です。社内インフラで使うアカウントやグループなど、**さまざまな情報を保存する場所**です。
- **Active の意味**: 紙の電話帳のように直しにくいものではなく、**必要なときに情報を簡単に作成・修正・変更・削除**できることから、**「生きている電話帳」** と呼ばれます。
- **AD 以前**: Windows NT 4.0 までは、アカウント情報を **SAM**（Security Account Manager）データベースに保存していました。

## 2. セキュリティの基本: 認証と認可

AD の構造で本人確認とアクセス制御を理解するために欠かせない 2 つの概念です。

### 認証（Authentication）

- **定義**: 「自分が誰であるかを証明する作業」です。
- **仕組み**: ユーザーがアカウントとパスワードを入力すると、認証要求が**ドメインコントローラー（DC）** に送られ、DC に保存された情報と一致すればそのユーザーで間違いないと**確認**します。

### 認可（Authorization）

- **定義**: **誰が何をできるか、できないか**を判断することです。
- 認可には**権利（Right）** と**アクセス許可（Permission）** の 2 種類があります。

| 区分 | 権利（Right） | アクセス許可（Permission） |
| --- | --- | --- |
| 定義 | 何かを**する**ことの許可 | 何かを**使う**ことの許可 |
| 例 | コンピューターのシャットダウン、ネットワークからのアクセス、リモートデスクトップ接続 | フォルダーの読み取り、ファイルの書き込み |
| 重要な特徴 | Administrator はすべての権利を持つため、スーパーアカウントと呼ばれます。 | そのオブジェクトの**所有者だけ**が付与できます。 |
| 所有権 | 他人のオブジェクトのアクセス許可を変えるには、別途**所有権の取得**の権利が必要です。 | — |

## 3. データを守る方式: 暗号化

ネットワーク通信でデータを保護する方式です。

![Symmetric, asymmetric and hybrid encryption](../images/ad-encryption.svg)

### 共通鍵暗号

- **特徴**: **暗号化する鍵と復号する鍵が同じ**構造です。
- **長所**: 処理が簡単で高速です。
- **短所**: 暗号化されたデータを受け取る相手に**鍵を安全に渡す**必要があります。

### 公開鍵暗号

- **特徴**: **鍵が 2 つ**（非対称）あります。
  - **公開鍵（Public Key）**: 暗号化に使い、他の人と共有します。
  - **秘密鍵（Private Key）**: 復号に使い、**絶対に共有しません**。
- **仕組み**: 相手の**公開鍵**で暗号化したデータは、その相手の**秘密鍵**でしか復号できません。
- **基盤技術**: 証明書・認証局の技術、つまり **PKI**（Public Key Infrastructure）の基盤です。
- **長所**: セキュリティがはるかに高いです。

### 電子署名（Digital Signature）

- **目的**: そのデータを**送ったのが本当にその人か**（身元）を証明します。
- **仕組み**: 送信者が自分の**秘密鍵**で署名し、受信者は送信者の**公開鍵**で確認します。

### ハイブリッド暗号（混合方式、HTTPS）

- ほとんどの暗号化ソリューションは、公開鍵の**安全性**と共通鍵の**速さ**を組み合わせたハイブリッド方式を使います。
- **原理**: 最も重要な**共通鍵**そのものは安全な**公開鍵**方式で暗号化して渡し、**その後の大容量データ通信**は速くて効率的な**共通鍵**方式で行います。

## 4. ドメイン vs ワークグループ

Windows 環境で**認証を誰が管理するか**による区分です。

| 区分 | ワークグループ（Workgroup） | ドメイン（Domain） |
| --- | --- | --- |
| 既定 | Windows インストール時の既定値です。 | Active Directory を構成して設定します。 |
| 認証の主体 | 各コンピューターがローカルでアカウントとパスワードを管理します。（ローカル認証） | 中央のシステムであるドメインコントローラー（DC）が認証を処理します。 |
| AD との接続 | AD には接続されていません。 | ドメインに接続することを「ドメインに参加する」と言います。 |
| 長所 | シンプルで個別に管理でき、小規模な環境に適しています。 | SSO が可能で、セキュリティと認証・認可を 1 か所ですべて管理できます。 |
| 短所 | コンピューターごとにアカウントとパスワードを入力する必要があります。 | 中央のシステム（DC）が壊れると、認証の仕組み全体が動かなくなります。 |

> 2 つの方式を分ける核心は、**ID の認証（Authentication）を誰が行うか**です。

## 5. たとえで見る AD

AD 環境は**中央図書館システム**のようなものだと考えるとわかりやすいです。

- 中央図書館（**DC**）に身分を登録（**アカウント作成**）すれば、発行された 1 枚の会員証（**SSO**）で社内のすべての資料室（**コンピューター、サーバー**）を利用できます。
- 各資料室は、その会員証が有効かどうかを**中央図書館に問い合わせて**から扉を開けます。
- 図書館が閉まったり（**DC の障害**）、会員証が取り消されたり（**アカウント削除**）すると、その人はもうどの資料室にも入れません。

## まとめ

- AD の最大の目的は **SSO** です。アカウント管理・認証・認可を **DC 1 か所で集中的に**処理します。
- **ディレクトリ**はアカウントやグループの情報を収めた「電話帳」で、**Active** はいつでも直せる「生きている」電話帳という意味です。AD 以前（NT 4.0）は **SAM** を使っていました。
- **認証**は「誰か」、**認可**は「何ができるか」です。認可は**権利（Right）** と**アクセス許可（Permission）** に分かれます。
- **共通鍵**は速いが鍵の受け渡しが課題で、**公開鍵**は安全で **PKI** と**電子署名**の基盤です。実際には両者を組み合わせた**ハイブリッド方式**（HTTPS）を使います。
- **ワークグループ**はローカル認証、**ドメイン**は DC が認証します。ドメインは便利ですが DC が止まると認証も止まるため、DC を冗長化します。
