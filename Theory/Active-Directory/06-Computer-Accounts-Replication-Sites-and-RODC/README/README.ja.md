## 1. コンピューターアカウントと AD

- コンピューターがドメインに参加すると、**コンピューターアカウント**が自動で作られます。
- コンピューターアカウントにも**パスワード**があり、コンピューターと DC の間の通信のために **30 日ごと**に自動で変わります。
- コンピューターと DC は、このパスワード情報をもとに**セキュアチャネル（Secure Channel）** を結んで通信します。
- コンピューターが **30 日以上** DC と通信しにくい場合は、VPN や DirectAccess を使わせるか、グループポリシーでコンピューターアカウントのパスワードの**最長有効期間**を延ばす必要があります。

## 2. AD アカウント管理のコツ

- **グループポリシーの適用先**: OU（組織単位）にはグループポリシーをリンクできますが、アカウントが既定で作られる **Users** や **Computers コンテナー**には、グループポリシーを個別にリンクできません。
- **既定の場所の変更**: アカウントが作られる既定の場所を OU に変えるには、**`redirusr`**（ユーザー）と **`redircmp`**（コンピューター）コマンドを使います。
- **一括作業ツール（LDIFDE）**: 部署や電話番号などのユーザー属性を AD に**一括で入れたり**、逆に AD のデータを**取り出したり**するときは **`LDIFDE`** を使います。

```cmd
redirusr "OU=NewUsers,DC=korea,DC=com"
redircmp "OU=NewComputers,DC=korea,DC=com"
```

## 3. AD の複製

### DC が複数あるとき

- DC が複数あると、すべての DC のデータが同じになるように**複製が継続的に**行われます。
- **マルチマスター方式**: 複数の DC の**どこででも**同時にデータを変更できます。
- **複製の主な目標**: 正確性、整合性、一貫性、そして高速な性能です。

### 複製の技術的な特徴

| 特徴 | 内容 |
| --- | --- |
| 属性単位の複製 | Windows Server 2003 から複製の単位が**属性単位**に変わり、同じオブジェクトでも別の属性が変更されれば競合なく統合されます。 |
| パーティションごとの複製 | AD データベースは丸ごとではなく、**パーティションごと**に複製されます。（スキーマ、構成、ドメイン、GC、アプリケーション） |
| 自動トポロジ | DC どうしがどう複製すれば最も効率的かを **AD が自動で設計**します。 |

## 4. サイトとサービス

AD は既定で、すべての DC が**高速なネットワーク**内にあると考えて複製します。しかし社内ネットワークが**遅い WAN 区間**で分かれていると、複製や認証に問題が起こることがあります。

**サイト（Site）** は、遅いネットワーク環境で AD の複製を制御し、ユーザーが**最も近い（速い）ネットワークの DC** を使うように誘導するため、ネットワーク構造をまとめる概念です。

![Sites and replication](../images/ad-sites-replication.svg)

### サイトの機能と構成

| 項目 | 内容 |
| --- | --- |
| 複製の制御 | サイト間（WAN）の複製の時間と頻度を調整し、回線の負担を減らします。 |
| サービスのローカライズ | クライアントが**自分のサイト内の DC** で認証するようにします。 |
| サイトの区分 | 高速に接続されたネットワーク（サブネット）単位でサイトを分けます。 |
| サイトリンク | サイトとサイトを結ぶ複製の経路です。 |
| コスト | サイトリンクごとにコストを付け、値の小さい経路を優先して使います。 |

## 5. RODC

### RODC とは？

- 通常の DC はデータの**読み取りと書き込み**の両方ができますが、**RODC（Read-Only Domain Controller）** は名前のとおり**読み取り専用**でのみ動作する DC です。
- **物理的にセキュリティが弱い拠点**（支社など）に設置し、DC が盗まれても重要な情報が渡らないようにするために使います。

![RODC at a branch office](../images/ad-rodc.svg)

### RODC のセキュリティ強化機能

- **パスワードを保存しない**: RODC は既定で、セキュリティに関わる重要な情報（パスワード）を保存しません。
- **キャッシュの指定**: 性能を上げるため、**特定のユーザー**のパスワードだけをキャッシュ（保存）するよう指定できます。こうすると、その拠点のユーザーの認証を速くしながら、セキュリティも保てます。

---

## まとめ

- ドメインに参加すると**コンピューターアカウント**が作られ、そのパスワードは **30 日ごと**に変わって DC と**セキュアチャネル**を結びます。
- **Users/Computers コンテナー**には GPO をリンクできないので、`redirusr`・`redircmp` で既定の場所を OU に変えます。一括作業には **LDIFDE** を使います。
- AD の複製は**マルチマスター**、**属性単位**（2003 から）、**パーティションごと**の複製で、トポロジは**自動**で作られます。
- **サイト**は遅い WAN 区間の複製を制御し、クライアントに**近い DC** を使わせます。サイト間は**サイトリンク**と**コスト**で結びます。
- **RODC** はセキュリティの弱い拠点向けの**読み取り専用 DC** で、既定ではパスワードを保存せず、**指定したユーザーだけをキャッシュ**します。
