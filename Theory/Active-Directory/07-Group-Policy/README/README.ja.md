## 1. グループポリシーとは？

AD を使う理由は大きく 2 つあり、そのうちの 1 つがグループポリシーです。

1. **認証の集中化（SSO）**: 1 回のログインですべてを済ませます。
2. **管理の集中化（GP）**: 会社や組織内の Windows クライアントとサーバーを管理する技術です。

### グループポリシーの長所

- **一括反映**: 多くの Windows 設定を中央から一度に適用できます。
- **強制適用**: 絶対に変わってはいけない設定を中央で固定できるので、**会社の標準**をつくれます。

### グループポリシーでできること

1. **セキュリティ設定**: Windows のセキュリティ設定を適用します。
2. **アプリケーション設定**: Windows を含むさまざまなアプリの設定を中央から反映します。
3. **ネットワーク設定**: ファイアウォール、IP セキュリティ、ネットワークドライブの接続などを一括で処理します。
4. **フォルダーリダイレクト**: ユーザープロファイルのフォルダーをサーバーに集め、バックアップと管理を簡単にします。

### 3 つの設定モード

| モード | 意味 |
| --- | --- |
| 有効（Enabled） | 設定を反映します。 |
| 無効（Disabled） | 設定を逆に（オフの方向に）反映します。 |
| 未構成（Not Configured） | ヌル（Null）値で、何も決めません。 |

## 2. グループポリシーの構成とリンク範囲

### コンピューターの構成とユーザーの構成

グループポリシーは大きく 2 つのブロックに分かれます。

| ブロック | 対象 | 適用のタイミング |
| --- | --- | --- |
| コンピューターの構成 | AD の**コンピューターアカウント** | コンピューターが**起動するとき** |
| ユーザーの構成 | AD の**ユーザーアカウント** | ユーザーが**ログオンするとき** |

### ポリシーのリンク範囲

グループポリシーを**どこにリンクして適用するか**を決める範囲です。

- **ドメイン**: AD の基本の範囲です。
- **組織単位（OU）**: ドメインの中で範囲を切り分けた単位です。
- **サイト**: ネットワーク構成に合わせてポリシーを反映できます。

> ユーザー 1 人、グループ 1 つ、コンピューター 1 台に**直接リンクすることはできません。** ポリシーはドメイン、OU、サイト単位でリンクされます。

## 3. グループポリシーの仕組み

私たちが「グループポリシー（GPO）」と呼んでいるものは、実際には 2 つの部分に分かれます。

![What a GPO is made of](../images/ad-gpc-gpt.svg)

1. **グループポリシーコンテナー（GPC）**: **AD の中**に保存され、ポリシーをどこに反映するかを結び付ける役割です。
2. **グループポリシーテンプレート（GPT）**: **実際の設定内容**を持ち、DC のインストール時に作られる **SYSVOL** フォルダーの中に保存されます。

---

## 4. グループポリシー（GPO）と基本設定（GPP）

| 区分 | グループポリシー（GPO） | グループポリシーの基本設定（GPP） |
| --- | --- | --- |
| 強制力 | 厳格に強制適用されます。（Strictly Enforced） | 適用はされますが、ユーザーが変更できます。 |
| 変更できるか | ユーザーは設定画面で変更できません。（無効化される） | ユーザーは値を変更できますが、定期的に元の値が再び反映されます。 |
| 用途 | セキュリティ設定や会社の標準など、強制適用が必要な部分 | GPO では設定できない追加の領域や、GUI ベースの簡単な設定 |

一般に、強制適用が必要なセキュリティ設定や会社の標準には **GPO** を使うほうがはるかに効率的です。

### ポリシー適用のタイミング（Refresh）

ポリシーはコンピューターの起動時やユーザーのログオン時だけでなく、**定期的に**更新されます。

- **既定の周期**: 90 分にランダムなオフセット ±30 分が加わり、**60〜120 分**の間に反映されます。
- **セキュリティ設定**: 変更がなくても **16 時間ごと**に再び反映されます。
- **強制更新**: 待ちたくなければ **`gpupdate`** コマンドですぐに反映します。

```cmd
gpupdate /force
```

## 5. ポリシーの処理順序とフィルタリング

### ポリシーの処理順序

ポリシーはいくつかの段階を下りながら反映され、**最後に反映された値が最終的な結果**になります。

![Group Policy processing order](../images/ad-gpo-order.svg)

1. ローカルグループポリシー
2. サイト
3. ドメイン
4. OU

### アカウントポリシー

**パスワードポリシー**のようなアカウントポリシーは、**ドメイン単位でのみ**反映されます。

> 例: ドメインでパスワードの最小の長さを 8 文字にしたなら、特定の OU で 3 文字に設定しても **8 文字**が適用されます。

### 強制と継承のブロック

ポリシーどうしの競合を防いだり、優先順位を決めたりできます。

- **強制（Enforce）**: 上位（例: ドメイン）のポリシーを下位に**強制的に下ろし**、上書きできないようにします。
- **継承のブロック（Block Inheritance）**: 下位の OU が**上から来るポリシーを受け取らないように**します。（強制されたポリシーはブロックできません。）

### セキュリティフィルターと WMI フィルター

- **セキュリティフィルター**: 特定のグループやユーザーを除外したり、目的のグループにだけポリシーが反映されるようにアクセス許可を調整します。
- **WMI フィルター**: OS のバージョンなど、**コンピューターの条件**に合わせてポリシーを適用します。

## 6. ポリシーの確認ツールと管理用テンプレート

### ポリシー結果の確認

- **ポリシーの結果セット（RSoP）**: グループポリシー管理コンソール（**GPMC**）のグループポリシーの結果や **`rsop.msc`** で、最終的にどのポリシーが反映されたかを確認します。
- **`gpresult`**: コマンドプロンプトで、現在受け取っているポリシーを確認するときに使います。

```cmd
gpresult /r
```

### 管理用テンプレート

- コントロールパネルや Windows コンポーネントなど、**Windows の基本的な設定が集まっている場所**です。
- ほとんどの必要な設定はここで行います。

## まとめ

- AD を使う 2 つの理由は、**認証の集中化（SSO）** と**管理の集中化（グループポリシー）** です。グループポリシーは設定を**一括で反映**し、**強制適用**します。
- 設定モードは**有効 / 無効 / 未構成**です。**コンピューターの構成は起動時**、**ユーザーの構成はログオン時**に反映されます。
- ポリシーは**ドメイン・OU・サイト**にだけリンクでき、個々のユーザー・グループ・コンピューターには直接リンクできません。
- GPO は **GPC**（AD 内、リンク情報）と **GPT**（SYSVOL、実際の設定）で構成されます。強制が必要なら **GPO**、柔軟な既定値は **GPP** です。
- 更新は **90 分 ± 30 分**、セキュリティ設定は **16 時間ごと**、すぐ反映するには **`gpupdate`** です。
- 処理順序は**ローカル → サイト → ドメイン → OU**で、最後の値が勝ちます。**アカウントポリシーはドメインでのみ**適用されます。**Enforce**・**Block Inheritance**・**セキュリティ/WMI フィルター**で範囲を調整します。
- 結果は **RSoP（`rsop.msc`、GPMC）** と **`gpresult`** で確認します。
