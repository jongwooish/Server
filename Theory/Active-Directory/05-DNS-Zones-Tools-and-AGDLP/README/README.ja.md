## 1. DNS ゾーンと主なレコード

AD では DNS が要なので、DNS をよく理解しておく必要があります。DNS サーバーは**ゾーン（Zone）** を作って名前を管理します。

### 前方参照と逆引き参照

| 参照 | 役割 | 例 |
| --- | --- | --- |
| 前方参照 | ドメイン名 → IP アドレス | `www.korea.com` → `192.168.0.1` |
| 逆引き参照 | IP アドレス → ドメイン名 | `192.168.0.1` → `www.korea.com` |

### DNS ゾーンの種類

![DNS zone types](../images/ad-dns-zones.svg)

1. **プライマリゾーン（Primary Zone）**: 名前を IP に変換する基本のメインゾーンです。読み取りと書き込みができます。
2. **セカンダリゾーン（Secondary Zone）**: プライマリゾーンの**読み取り専用のバックアップ**です。
3. **スタブゾーン（Stub Zone）**: そのゾーンを提供する DNS サーバーがどこかを示す **NS レコード**と、そのサーバーの **A レコードだけ**を持つゾーンです。

### 主な DNS レコード

| レコード | 役割 |
| --- | --- |
| A | 最も基本的なレコードで、名前を IP アドレスに対応付けます。 |
| CNAME | 別の名前（A レコード）を指す**別名**です。 |
| MX | そのドメインの**メールサーバー**のアドレスを示します。 |
| PTR | 逆引き参照ゾーンに作成し、IP アドレスから名前を示します。 |

### 動的更新（Dynamic Update）

クライアントが**自分のホスト名を自分で DNS に登録する**機能です。

- 一般的な DNS ではあまり使いませんが、AD では登録時にセキュリティを適用する**セキュリティで保護された動的更新**を使います。
- **保護されていない動的更新**はごみデータがたまるおそれがあるので、使わないほうがよいです。

## 2. ドメインコントローラーの追加インストール

DC が 1 台だけだと、その DC が停止したときに認証が止まります。そのため実務では **DC を 2 台以上**インストールすることが推奨されます。

### Server Core の活用

- AD ドメインコントローラーは、容量が小さくパッチの少ない **Windows Server Core** にもインストールできます。
- Core にはグラフィカルなツールがないため、すべての作業を **PowerShell** やコマンドで行います。基本設定には **`sconfig`** を活用します。
- GUI サーバーの**サーバーマネージャー**から Core サーバーをリモートで管理することもできます。

```powershell
# AD DS の役割をインストール
Install-WindowsFeature -Name AD-Domain-Services -IncludeManagementTools

# 既存のドメインに DC として追加（昇格）
Install-ADDomainController -DomainName "korea.com" -InstallDns
```

> **ヒント**: GUI でも CLI でも、DC に昇格する前に **DNS が既存の DC を指すように**設定しておく必要があります。

## 3. AD の管理ツールとごみ箱

### 管理ツール

ユーザーやグループを作るときに使うツールは 2 つあります。

1. **Active Directory ユーザーとコンピューター（ADUC）**: 以前からよく使われてきたツールです。
2. **Active Directory 管理センター（ADAC）**: 新しい管理ツールです。作業するたびにその作業の **PowerShell コマンドを表示してくれる**ので、あとでスクリプトを書くときに便利です。

### AD のごみ箱

- 以前は AD のオブジェクトを誤って削除すると、**バックアップからしか**復元できませんでした。
- Windows Server 2008 R2 からは、**AD のごみ箱**を有効にすると、削除したユーザーやグループを簡単に復元できます。

## 4. グループの種類とスコープ

AD をうまく使うには、グループをうまく活用する必要があります。ユーザーをグループにまとめてグループに権限を与えれば、中央で管理できます。

### グループの種類

| 種類 | 用途 |
| --- | --- |
| 配布グループ | メールを送るためのまとまりです。**セキュリティ識別子（SID）がないため**、権限を与えられません。 |
| セキュリティグループ | **権限の付与**に使います。メール用としても使えます。 |

### グループのスコープ

| スコープ | 用途 |
| --- | --- |
| グローバルグループ | **人をまとめる**用途です。 |
| ドメインローカルグループ | **権限を与える**用途です。 |
| ユニバーサルグループ | **フォレスト全体**を含みます。ドメインが複数あるとき、グローバルグループをまとめるのに便利です。 |

---

## 5. グループ管理の戦略 AGDLP

AGDLP は、権限をユーザーに直接与えるのではなく、**グループを段階的に経由して**与える戦略です。すべての権限管理を AD で処理できるようにする、AD を使う主な理由の 1 つでもあります。

![AGDLP](../images/ad-agdlp.svg)

- **A** - Account: ユーザーアカウントを作ります。
- **G** - Global Group: ユーザーをグローバルグループに入れます。
- **DL** - Domain Local Group: グローバルグループをドメインローカルグループに入れます。
- **P** - Permission: ドメインローカルグループに権限を与えます。

## まとめ

- DNS ゾーンは**プライマリ**（読み書き）、**セカンダリ**（読み取り専用のバックアップ）、**スタブ**（NS + A のみ）に分かれます。
- 主なレコードは **A**（名前→IP）、**CNAME**（別名）、**MX**（メールサーバー）、**PTR**（IP→名前）です。AD では**セキュリティで保護された動的更新**を使います。
- DC は **2 台以上**置きます。Server Core では `sconfig`、`Install-WindowsFeature`、`Install-ADDomainController` を使い、昇格の前に **DNS を既存の DC に**向けます。
- 管理ツールには **ADUC** と **ADAC** があり、ADAC は PowerShell コマンドを表示します。**AD のごみ箱**を有効にすると、削除したオブジェクトを簡単に復元できます。
- グループの種類は**配布**（SID なし）と**セキュリティ**、スコープは**グローバル**（人）、**ドメインローカル**（権限）、**ユニバーサル**（フォレスト全体）です。
- **AGDLP**: アカウント → グローバルグループ → ドメインローカルグループ → 権限。
