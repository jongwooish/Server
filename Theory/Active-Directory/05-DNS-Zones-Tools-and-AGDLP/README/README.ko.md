## 1. DNS 영역과 주요 레코드

AD에서 DNS는 핵심이므로 DNS를 잘 이해해야 합니다. DNS 서버는 **영역(Zone)** 을 만들어 이름을 관리합니다.

### 정방향 조회와 역방향 조회

| 조회 | 하는 일 | 예시 |
| --- | --- | --- |
| 정방향 조회 | 도메인 이름 → IP 주소 | `www.korea.com` → `192.168.0.1` |
| 역방향 조회 | IP 주소 → 도메인 이름 | `192.168.0.1` → `www.korea.com` |

### DNS 영역 종류

![DNS zone types](../images/ad-dns-zones.svg)

1. **주 영역 (Primary Zone)**: 이름을 IP로 바꿔 주는 기본 메인 영역입니다. 읽기와 쓰기가 가능합니다.
2. **보조 영역 (Secondary Zone)**: 주 영역의 **읽기 전용 백업본**입니다.
3. **스텁 영역 (Stub Zone)**: 해당 영역을 서비스하는 DNS 서버가 어디인지 알려 주는 **NS 레코드**와 그 서버의 **A 레코드만** 가진 영역입니다.

### 주요 DNS 레코드

| 레코드 | 역할 |
| --- | --- |
| A | 가장 기본 레코드로, 이름을 IP 주소로 지정합니다. |
| CNAME | 다른 이름(A 레코드)을 가리키는 **별칭**입니다. |
| MX | 해당 도메인의 **메일 서버** 주소를 알려 줍니다. |
| PTR | 역방향 조회 영역에 만들어 IP 주소를 이름으로 알려 줍니다. |

### 동적 업데이트 (Dynamic Update)

클라이언트가 **스스로 자신의 호스트 이름을 DNS에 등록**하는 기능입니다.

- 일반 DNS에서는 잘 쓰지 않지만, AD에서는 등록할 때 보안을 적용하는 **보안 동적 업데이트**를 사용합니다.
- **보안되지 않은 동적 업데이트**는 쓰레기 데이터가 쌓일 수 있으니 사용하지 않는 것이 좋습니다.

## 2. 도메인 컨트롤러 추가 설치

DC가 한 대뿐이면 그 DC가 다운될 때 인증이 멈춥니다. 그래서 실무에서는 **DC를 2대 이상** 설치하는 것을 권장합니다.

### 서버 코어 버전 활용

- AD 도메인 컨트롤러는 용량이 작고 패치가 적은 **Windows Server Core** 버전에도 설치할 수 있습니다.
- 코어 버전에는 그래픽 도구가 없어서 모든 작업을 **PowerShell**이나 명령어로 해야 합니다. 기본 설정에는 **`sconfig`** 를 활용합니다.
- GUI 서버의 **서버 관리자**에서 코어 서버를 원격으로 관리할 수도 있습니다.

```powershell
# AD DS 역할 설치
Install-WindowsFeature -Name AD-Domain-Services -IncludeManagementTools

# 기존 도메인에 DC로 추가 (승격)
Install-ADDomainController -DomainName "korea.com" -InstallDns
```

> **팁**: GUI든 CLI든 DC로 승격하기 전에 **DNS가 기존 DC를 가리키도록** 설정해야 합니다.

## 3. AD 관리 도구와 휴지통

### 관리 도구

사용자나 그룹을 만들 때 쓰는 도구는 두 가지입니다.

1. **Active Directory 사용자 및 컴퓨터 (ADUC)**: 예전부터 많이 쓰던 도구입니다.
2. **Active Directory 관리 센터 (ADAC)**: 새로운 관리 도구입니다. 작업할 때마다 그 작업의 **PowerShell 명령어를 보여 줘서** 나중에 스크립트를 짤 때 유용합니다.

### AD 휴지통

- 예전에는 AD 개체를 실수로 지우면 **백업본으로만** 복구할 수 있었습니다.
- Windows Server 2008 R2부터는 **AD 휴지통**을 활성화하면 지워진 사용자나 그룹을 쉽게 복구할 수 있습니다.

## 4. 그룹의 종류와 범위

AD를 잘 쓰려면 그룹을 잘 활용해야 합니다. 사용자를 그룹으로 묶어 그룹에 권한을 주면 중앙에서 관리할 수 있습니다.

### 그룹의 종류

| 종류 | 용도 |
| --- | --- |
| 배포 그룹 | 메일을 보내기 위한 묶음입니다. **보안 식별자(SID)가 없어서** 권한을 줄 수 없습니다. |
| 보안 그룹 | **권한 부여**를 위해 사용합니다. 메일용으로도 쓸 수 있습니다. |

### 그룹의 범위

| 범위 | 용도 |
| --- | --- |
| 글로벌 그룹 | **사람들을 묶는** 용도입니다. |
| 도메인 로컬 그룹 | **권한을 부여하는** 용도입니다. |
| 유니버설 그룹 | **포리스트 전체**를 포함합니다. 도메인이 여러 개일 때 글로벌 그룹들을 묶는 데 편리합니다. |

---

## 5. 그룹 관리 전략 AGDLP

AGDLP는 권한을 사용자에게 직접 주지 않고, **그룹을 단계적으로 거쳐** 주는 전략입니다. 모든 권한 관리를 AD에서 처리할 수 있게 해 주는, AD를 쓰는 주된 이유이기도 합니다.

![AGDLP](../images/ad-agdlp.svg)

- **A** - Account: 사용자 계정을 만듭니다.
- **G** - Global Group: 사용자를 글로벌 그룹에 넣습니다.
- **DL** - Domain Local Group: 글로벌 그룹을 도메인 로컬 그룹에 넣습니다.
- **P** - Permission: 도메인 로컬 그룹에 권한을 줍니다.

## 정리

- DNS 영역은 **주 영역**(읽기/쓰기), **보조 영역**(읽기 전용 백업), **스텁 영역**(NS + A만)으로 나뉩니다.
- 주요 레코드는 **A**(이름→IP), **CNAME**(별칭), **MX**(메일 서버), **PTR**(IP→이름)입니다. AD에서는 **보안 동적 업데이트**를 씁니다.
- DC는 **2대 이상** 둡니다. 서버 코어에서는 `sconfig`, `Install-WindowsFeature`, `Install-ADDomainController`를 사용하고, 승격 전에 **DNS를 기존 DC로** 지정합니다.
- 관리 도구는 **ADUC**와 **ADAC**가 있으며, ADAC는 PowerShell 명령어를 보여 줍니다. **AD 휴지통**을 켜면 지운 개체를 쉽게 복구합니다.
- 그룹은 **배포**(SID 없음)와 **보안** 그룹, 범위는 **글로벌**(사람), **도메인 로컬**(권한), **유니버설**(포리스트 전체)입니다.
- **AGDLP**: 계정 → 글로벌 그룹 → 도메인 로컬 그룹 → 권한.
