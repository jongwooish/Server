## 왜 IDC인가

IDC 안에 처음 들어가 봤다. 랙에 서버가 꽂혀 있고, 방화벽 뒤에 웹 서버와 DB가 나뉘어 있는 걸 실제로 보니까, 지금까지 기능반에서 과제 단위로 따로따로 만들던 서비스들이 실제로는 하나로 엮여서 돌아간다는 게 와닿았다.
그래서 "과제 풀이"가 아니라 "회사 하나의 인프라"를 처음부터 끝까지 만들어 보기로 했다.

## 기획서

### 상황

(주)쫑마켓은 직원 20명 규모의 온라인 쇼핑몰이다. 클라우드 비용이 계속 늘어서 IDC 랙 하나를 빌려 서버를 직접 운영하기로 했다. 나는 인프라 담당자다.

### 요구사항

| ID | 요구사항 | 어떻게 |
| --- | --- | --- |
| R1 | 인터넷에서 `https://www.jjongmarket.kr` 로 쇼핑몰 접속 | FW DNAT → 웹 VIP → Apache |
| R2 | 웹 서버 한 대가 죽어도 쇼핑몰 유지 | keepalived VRRP |
| R3 | 필요한 포트만 연다 | nftables 기본 차단 |
| R4 | 서버 관리는 관리망에서만, 재택은 VPN | VPN → MGMT만 허용 |
| R5 | 내부와 외부에 다른 DNS 응답 | BIND9 view |
| R6 | 상품 데이터 보관과 백업 | MariaDB + 매일 덤프 + 다른 서버에 보관 |
| R7 | 상태를 한 화면에서 | Prometheus + Grafana |
| R8 | 다음 담당자가 다시 만들 수 있게 | 문서 + Ansible |
| R9 | HTTPS 경고 없음 | 사설 Root CA |
| R10 | 모든 서버 시간 일치 | chrony |

### 제약

- VMware Workstation, Debian 13.2, VM 8대 (서버 6 CLI, 클라이언트 2 GUI)
- Host-only 망만 사용. 인터넷은 없다고 가정하고, 패키지 설치할 때만 NAT 어댑터를 잠깐 붙인다
- 대회 연습처럼 "되기만 하면" 끝이 아니라, 왜 그렇게 했는지 설명할 수 있어야 한다
